# Windows共通Coreの速度比較（ac0fd42）

対象は `ac0fd4276d98c3830c9a5446f828f11cb0fdb08d` のRust Releaseと、元版 `45e14f86558aa6ea34f2c2ecd038ba95ca8c3c46` のC# NativeAOTです。同じ辞書・設定でウォームアップ1回＋測定3回を、順序を逆にした2巡（各実装・各ケース6試行）実行しました。測定前後のソースと実行ファイルは不変で、他のビルドは並行実行していません。

**確定内容・全打鍵の途中状態とも21/21一致**。Balanced・学習／ライブ変換／予測／OSスペル／外部変換器OFFのメモリ内キー処理とJSON生成が対象です。TSF・候補描画・起動・変換器・メモリ消費・全候補順・全設定は含みません。

重なる部分文字列の誤字候補探索で、文字ごとの正規化結果を再利用しました。結合クラスの条件を満たす場合だけ連結し、他は従来の全体正規化を使います。長い候補を優先する順序と、正しい語に当たったら短い候補を止める条件を保持します。

元版の比較を2182入力へ拡大し、正常結果2045入力（置換1622／候補なし423）が一致。元版の137例外は別記し、Rustでは全2182入力を実行できました。最初の596入力も期待値が不変です。[条件](../../../parity/misspellings/README.md)。全185テスト・Rust 1.99の全体／TSF-server Clippyが成功。最終Releaseのx64／x86でABI・文節伸縮20入力列・選択再変換28操作・学習ワーカーも成功しました。

各入力列全体の中央値（末尾Enterを含む）です。Rust/C#は1より小さいほどRustが速い値です。

8/21ケースでRustが速く、13ケースはC#より遅い結果です。英語256キーはC# 1761.955ms／Rust 1008.310ms、URL256キーはC# 59.939ms／Rust 3.691msでした。日本語256キーはC# 1643.377ms／Rust 4230.685ms、短い日本語も今回はC# 2.422ms／Rust 3.042msで、引き続き改善が必要です。一律の高速化や完全移行は達成していません。

[前回561b8f8](561b8f8.md)とは測定時点が異なりC#側も変動しています。版間の時間差をこの変更だけの厳密な効果量として扱いません。今回も各ケース6試行の限定測定です。
