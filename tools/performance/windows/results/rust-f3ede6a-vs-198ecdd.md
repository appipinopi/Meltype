# 旧Rustと198ecddの同一コンパイラ比較

f3ede6aをrustc 1.99.1でビルドし、同じ1.99.1で作られた198ecddの固定実行ファイルと比較。5試行・2ウォームアップ×順序を逆にした2巡。全21入力の確定・比較対象の途中状態は一致。新しい版が遅いのは7/21で、14/21は速かった。

| 入力 | f3ede6a (ms) | 198ecdd (ms) | 新/旧 |
|---|---:|---:|---:|
| japanese_256 | 1369.712 | 1258.998 | 0.919 |
| mixed_64 | 50.588 | 52.192 | 1.032 |
| mixed_256 | 1155.378 | 967.172 | 0.837 |
| english_256 | 656.049 | 481.504 | 0.734 |

以前のf3ede6aはrustc 1.94.1、198ecddは1.99.1で、試行数も異なっていた。その比較で見えた約25〜36%の悪化を、今回のコード変更だけの速度低下とは断定できない。同一コンパイラでは日本語256キーは約8.1%、混在256キーは約16.3%改善し、混在64キーは約3.2%悪化した。

ただしRAMピークは約42.805→45.883MiBへ増えている。FST導入だけでRAM全体が必ず小さくなるわけではない。

FST前方一致を直接ノード走査へ変更した部分測定は改善しているが、各ソース・依存・処理の変更から総時間への寄与を分解したプロファイルではない。全ての遅延原因が解決したとはしない。
