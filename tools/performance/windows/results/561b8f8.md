# Windows共通Coreの速度比較（561b8f8）

対象は `561b8f86583dead3ba4cff1917eaa20d9789d8b5` のRust Releaseと、元版 `45e14f86558aa6ea34f2c2ecd038ba95ca8c3c46` のC# NativeAOTです。同じ辞書・設定で各ケースをウォームアップ1回＋測定3回、順序を逆にした2巡（各実装・各ケース6試行）測定しました。測定前後のソースと実行ファイルは不変で、他のビルドは並行実行していません。

**確定内容・全打鍵の途中状態とも21/21一致**。学習・ライブ変換・予測・OSスペル・外部変換器を無効にしたBalancedのメモリ内キー処理とJSON生成です。TSF配送・候補描画・起動・変換エンジン・メモリ消費・候補一覧・全設定の比較ではありません。

ASCIIの読みでは一致し得ない書き間違い候補の探索を省きました。この条件は辞書の誤記と正規化したキーから導きます。全185テストとRust 1.99の全体／TSF-server Clippyが成功。元版の書き間違い辞書596入力を採取し、正常に返した459入力は全文が一致。残る137入力の元版例外は別に保存し、Rustでは全596入力を実行できることを確認しました。[比較条件](../../../parity/misspellings/README.md)。
